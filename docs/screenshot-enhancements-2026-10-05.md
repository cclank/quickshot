有几处需要明确区分：

- 选区阶段已经裁切截图，编辑器尚无再次裁剪原图的工具。背景渲染中的 `cropWidth` 等变量用于背景铺满，不构成图片裁剪功能。
- 编辑器底部显示的缩放比例由窗口大小自动计算，尚无手动放大、平移或 100% 查看入口；选区放大镜和桌面贴图缩放属于另外两个场景。[Stage.tsx](../src/components/editor/Stage.tsx:295)
- 当前只能保存一套默认美化样式，尚无带名称的多套预设库。
- `history.ts` 是编辑器内标注撤销/重做的数据结构，尚无截图历史库或可重新打开的编辑工程。
- 加载 JPG/WebP 壁纸的 MIME 支持用于资源读取。编辑器输出、IPC 校验与保存流程目前均围绕 PNG，尚无 JPG/WebP 导出选项。

## 候选功能与优先级

优先级和投入规模是基于当前结构的产品与工程判断，用于比较排期，没有经过原型验证或工期测量。

| 建议轮次 | 功能 | 用户获得的价值 | 当前缺口与投入判断 |
| --- | --- | --- | --- |
| 首批 | 图片导入：打开文件、拖入、粘贴图片 | 旧截图、别人发来的图片也能标注和美化 | 没有导入入口；可复用预览会话与编辑器，投入中等 |
| 首批 | 编辑器裁剪、手动缩放与平移 | 截完后继续删去无关区域；精确标注小字和细节 | 自动适应窗口已有；裁剪状态、坐标与撤销需扩展，投入中等 |
| 首批 | 局部放大标注与聚光灯 | 教程中放大一个按钮，或压暗其他区域突出操作重点 | 标注类型、命中检测、编辑与导出需增加，投入中等 |
| 首批 | 多套命名样式预设 | 一键切换“教程”“产品展示”“社交分享”等风格 | 已有参数存储和单套默认；扩展列表与管理，投入较小 |
| 第二批 | 导出尺寸、PNG/JPG/WebP 与质量控制 | 控制成品尺寸和文件大小，减少跨应用压缩 | 渲染器、保存 IPC、文件名与校验都需适配，投入中等 |
| 第二批 | 多图拼接与对比排版 | 横排/竖排教程步骤、前后对比、统一间距和背景 | 当前单图画布；先做固定排版，再考虑自由叠图，投入中等至较大 |
| 第二批 | 延时截图与复用上次区域 | 截下拉菜单、悬浮提示、同一位置的前后状态 | 主进程计时与会话状态、显示器变化处理需增加，投入中等 |
| 第二批 | OCR 增强与二维码 | 合并换行、仅识别选中区域、读取二维码 | OCR 已有；文本整理较小，框选/二维码与多平台接口需另做 |
| 后续 | 本地截图历史与可编辑工程 | 找回近期截图，关闭后继续改标注和样式 | 需管理图片、标注、样式、版本与保留策略，投入较大 |
| 后续 | 滚动长截图 | 捕捉长网页、聊天记录、长代码 | 需连续采集、帧对齐、去重、固定栏处理和失败恢复，投入较大 |

若用户以日常办公为主，导入、裁剪、延时截图、OCR 整理更直接。若以教程和产品内容为主，局部放大、聚光灯、样式预设、多图排版更有辨识度。

## 首批的实现边界与验收点

### 1. 已有图片进入同一编辑流程

增加“打开图片”入口，并支持拖入和粘贴。主进程把图片解码为现有预览会话使用的数据；取消导入时保留当前编辑内容。已有美化参数、标注、导出与 OCR 应继续可用。需要分别验证 macOS/Windows 的文件和剪贴板入口，普通图片的逻辑尺寸不能直接套用 Retina 截图密度。

### 2. 裁剪与查看细节

增加裁剪框与确认/取消，保留原图以便撤销；同时提供适应窗口、100%、放大/缩小和空格平移。裁剪需要与标注共用文档历史，处理裁剪后坐标、画面比例和 OCR 的有效区域。验收包含已有文字/箭头跨裁剪边界、连续撤销/重做、1x/2x 图片及大图查看。

### 3. 可编辑的局部放大与聚光灯

局部放大保留来源区域与展示区域，支持倍率、边框和移动；聚光灯支持矩形或圆形区域、遮罩强度。两者进入现有的选择、缩放、撤销与导出体系。放大取样应遵循打码结果，避免同一截图中的已遮盖内容在放大框里重新出现；预览、复制、保存需保持一致。

### 4. 多套样式预设

在现有 `StyleSettings` 和默认样式上增加名称、保存、重命名、删除和应用。先复用现有渐变、边距、阴影、框架、比例与水印参数，不新增外部素材。应用预设影响美化参数，保留已画标注；升级时承接用户现有默认样式。

## 后续功能的结构依赖

当前编辑器历史仅持有 `Annotation[]`，原图与样式分别存放。裁剪、旋转、多图和工程恢复会受益于一个带版本的编辑文档，包含图片引用、裁剪/变换、标注和美化参数。首批可只引入单图与裁剪所需的最小结构，避免一次改造成完整排版工具。

导出格式应贯通渲染结果、主进程验证、扩展名和保存入口。透明图输出 JPG 时要有明确的背景填充；复制和贴图可以继续使用 PNG。缩放预览与改变导出像素尺寸需要分别控制。

OCR 定位与辅助打码需要两端返回文本框等数据。目前 [macOS helper](../native/quickshot-ocr/main.swift:40) 和 [结果解析器](../electron/ocrResult.ts:1) 只返回文字与行数。文本规则匹配只能提供候选，不应宣称识别了所有敏感信息。已有实心矩形可用于手工覆盖，专用打码模式还需定义覆盖顺序与交互。

长截图可从手动滚动、多帧预览、手动调整接缝开始；自动滚动需在 macOS 和 Windows 分别验证。固定页头、动画、懒加载和滚动容器可能使拼接失败，应允许调整或保留原帧。这里是实现方向，尚无可运行原型。

历史记录保持本地，并让用户选择是否启用及保留数量/时间。工程文件需要版本、图片与标注一起保存；单纯保存 PNG 无法恢复编辑对象。
